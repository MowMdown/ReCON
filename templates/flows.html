Flow help

What a flow is

A flow is a saved list of RCON steps. Every step runs at its own offset from the flow's 0 point: before it, on it, or after it. A restart flow, for example, counts down with warnings before the 0 point, shuts the server down on it, and unlocks it afterwards.

How a flow starts

Each flow has one trigger, picked in the edit dialog:

  • Manual - only when you press Run.
  • Schedule - on a cron schedule, while the flow is Enabled.
  • On player join - once for each player who joins, while the flow is Enabled.

Any flow can also be started by hand with Run, unless it uses $player or $name.

Making your first flow

  • Press New flow, give it a name (up to 48 characters) and write its steps (see Writing steps).
  • Pick a trigger. For Schedule, type a cron expression; the text under it explains it in plain English.
  • Save. Schedule and player-join flows start disabled: press Enable when you are ready.

Step format

One step per line: offset | command. Lines starting with // are comments.

-60m | say -1 Server is going to restart in $minutes minutes!
-3m  | #lock
-1m  | #kickall Restarting now
0m   | #shutdown
+90  | #unlock
cancel | say -1 Server restart cancelled.

Offsets

  • -60m runs 60 minutes before the 0 point, 0m runs on it, +90 runs 90 seconds after it.
  • Units are s, m and h. No unit means seconds, so -90 is 90 seconds before.
  • Any offset other than 0 needs a + or - sign. The largest offset is 7 days.

Where the 0 point is

  • Schedule: the cron time. A flow starting at -60m begins its countdown an hour earlier.
  • Run (any trigger): placed so the earliest step fires the moment you press Run, and the rest follow at their offsets.
  • On player join: the moment the player finished joining, so only 0s and + offsets are allowed.

Variables and cancel steps

  • $minutes and $seconds become how long before the 0 point that step runs (0 for steps on or after it).
  • $player and $name only work in On player join flows (see Player join).
  • cancel | command lines run only if you press Stop before the 0 point arrives. Use them to undo a countdown, for example a "restart cancelled" message.

Rules worth knowing

  • New schedule and player-join flows are saved disabled. Press Enable to switch them on.
  • Changing an existing flow's trigger saves it disabled too, so a restart flow can never start firing on every join by accident.
  • A blank or * * * * * schedule means "no schedule": pick the Manual trigger for that instead.
  • Run works with every trigger, so you can test a scheduled flow without waiting for its time. Flows that use $player or $name are the exception.

Cron expressions

Five fields: minute hour day-of-month month day-of-week, in the server's time zone (set TZ on the container). The text under the field explains what you typed in plain English, shows the next three runs, and when the next countdown starts.

  • 0 6 * * * every day at 06:00
  • 0 */6 * * * every 6 hours (00:00, 06:00, 12:00, 18:00)
  • 30 4 * * 1,4 Mondays and Thursdays at 04:30
  • 0 5 * * 1-5 weekdays at 05:00
  • 0 3 1 * * the 1st of every month at 03:00
  • @daily, @hourly, @weekly, @monthly shortcuts also work.

Field syntax

  • * any value, 1,4 a list, 1-5 a range, */15 every 15th.
  • Months and weekdays accept names: jan-dec, sun-sat. Sunday is 0 or 7.
  • If both day-of-month and day-of-week are restricted, a day matches when either does (standard cron).

Countdowns and app restarts

  • The cron time is the 0 point. A flow that starts at -60m with 0 6 * * * begins at 05:00.
  • If the app restarts during a scheduled countdown it rejoins it and skips steps whose time has passed. Manually started runs are not resumed.

How joins are detected

The app reads the player list every 5 seconds. While a player is still on the loading screen BattlEye shows (Lobby) after their name; they count as joined on the first check where that tag is gone, and every enabled On player join flow then runs once for them.

0s   | say $player Welcome to our server, $name!
+60  | say $player Type /help for the rules.

Variables

  • $player becomes the joining player's number (what say and kick need).
  • $name becomes their name.

Rules

  • Offsets count from when the join was seen, so use 0s or + offsets only.
  • Several players can be in progress at once; they share one log and one Stop button, which stops all of them.
  • Players already online when the app starts are not greeted. After the game server restarts, everyone who reconnects is.
  • Flows using $player or $name can't be started with Run or given another trigger.
  • Cancel steps never run for join flows: there is no countdown to undo.

Commands you can use in steps

  • Any BattlEye RCON command, such as say -1 text, #lock, #unlock, #shutdown or kick 3 reason.
  • kickall [reason] or #kickall [reason] kicks every connected player. With no reason it uses "Server restarting".

Messages

  • say -1 text messages everyone.
  • say <id> text messages one player; in join flows use say $player text.

Retries

#lock and #unlock are retried if the server doesn't answer, since repeating them is harmless. Other commands are sent once so a message is never shown twice. #shutdown often goes unanswered because the server stops.

Flow buttons

  • Enable / Disable turns a Schedule or On player join trigger on or off. Manual flows have nothing to enable, so the button is greyed out.
  • Run / Stop switches with the flow's state. Run starts the flow immediately: the earliest step fires right away and the rest follow at their offsets. Stop halts a running flow.
  • Edit changes the name, steps, trigger or schedule. Delete removes the flow (not while it is running).
  • Drag a row up or down to reorder the list.

Status, Last run and Next run

  • Idle - waiting for its next trigger (never run, or the last run finished normally).
  • Running - 45m45s - counting down to the flow's 0m step. Once that step is reached, or if the flow has no - offsets, it just shows Running.
  • Error - a command in the last run failed: RCON couldn't be reached or the server didn't answer. The other steps still ran; check the log under the list.
  • Stopped - the last run was ended with the Stop button.
  • Last run is when the flow was last started (for a join flow, the last player it ran for). It resets when the app restarts.

Export and import

  • Export downloads every flow (name, schedule and steps) as flows.json. The schedule value holds the trigger: "manual", "on-join" or a cron expression.
  • Import adds the flows from such a file to the bottom of the list, disabled, even if they already exist. A blank or * * * * * schedule imports as Manual, and names longer than 48 characters are shortened.

Quick commands

The #Lock, #Unlock, #Shutdown and #Kick All buttons at the top right send that command to the server immediately. Shutdown and Kick All ask for confirmation first.

Restart flows

  • Put #kickall at least a minute before 0m | #shutdown, since the sweep takes a few seconds.
  • Set +90 (or more) for #unlock to leave time for the server to restart and RCON to log in again.
  • #lock a couple of minutes before the shutdown so nobody joins just to be kicked.

General

  • A flow runs one copy at a time; pressing Run on a running flow does nothing.
  • To start a flow from an outside task scheduler, POST to /api/flows/<id>/run. Add {"minutes": 10} to put the 0 point 10 minutes away; steps that would already be in the past are skipped.
  • Run a new restart flow on a test server first, or use a Manual copy with only say lines to check the timing.
  • Each flow's log appears under the list while it runs and stays there after it finishes.
