Flow help

What a flow is

A flow is a small script of RCON commands. It runs one step per second (a tick): every command takes one tick, so a list of commands goes out one second apart. A restart flow, for example, counts down with warnings, locks the server, kicks everyone and shuts it down.

say -1 Kicking everyone in 10 seconds.
wait 10s
#kickall Maintenance

How a flow starts

Each flow has one trigger, picked in the edit dialog:

  • Manual - only when you press Run.
  • Schedule - on a cron schedule, while the flow is Enabled.
  • On player join - once for each player who joins, while the flow is Enabled.

A flow can also have a Timer: a delay before the script starts, or, for a scheduled flow, a countdown to the scheduled time (see Timer). Commands in the Cancel field are sent if you press Stop.

Making your first flow

  • Press New flow, give it a name (up to 48 characters) and write its script (see Script).
  • Pick a trigger. For Schedule, type a cron expression; the text under the fields explains it in plain English and shows when the run starts and ends.
  • Save. Schedule and player-join flows start disabled: press Enable when you are ready.

Lines

  • One command per line. The script runs from the top, one command per tick.
  • Lines starting with // are comments. Blank lines are removed when you save; use a // line to keep a visual gap.
  • $name = value lines set a variable and take no time.
  • The run ends after the last line (or, in a countdown, when the Timer reaches 0).

Commands you can use

  • Any BattlEye RCON command, such as say -1 text, #lock, #unlock, #shutdown or kick 3 reason.
  • kickall [reason] or #kickall [reason] kicks every connected player. With no reason it uses "Server restarting".
  • say -1 text messages everyone; say <id> text messages one player (say $player text in a join flow).

wait and stop

  • wait 10s pauses for that many ticks and sends nothing. Above, the say goes out on tick 1 and #kickall on tick 12.
  • stop ends the run straight away. The Cancel commands are not sent.

Times

  • Times need a unit: 30s, 5m, 1h, and combinations largest first, such as 1m30s or 1h3m15s.
  • A number without a unit is an error (wait 5 - did you mean 5s or 5m?). Only 0 needs no unit.

Variables

VariableValue
$playersHow many players are online (from the 5-second player check).
$timerSeconds left in a countdown (see Timer).
$player $name $ip $guid $pingThe player's number, name, IP, GUID and ping, in On player join flows and inside for each player.
$anythingYour own variable: $msg = Restarting soon. Each run starts with none set.

Time left in messages: @ words

These are replaced with the time left in a countdown when the command is sent.

WordMeansAt 1h 1m 5s left
@hours @minutes @secondsTotal time left in that unit1, 61, 3665
@hour @minute @secondClock parts (minute and second are 2 digits)1, 01, 05
 
$warn | say -1 Server restarts in @minutes minutes!
5m    | say -1 Time remaining @hour:@minute:@second

Retries

#lock and #unlock are retried if the server doesn't answer, since repeating them is harmless. Other commands are sent once so a message is never shown twice. #shutdown often goes unanswered because the server stops.

The Timer field

TimerWhat happens
EmptyThe script starts as soon as the flow is triggered.
DelayThe script starts the Timer's length after the trigger: after Run is pressed, after the player joins, or (After schedule) after the cron time. For Manual and On player join flows the field is called Delay.
CountdownScheduled flows only, set to Before schedule: the run starts the Timer's length before the cron time, and $timer counts the seconds down to 0 at it. The run ends at 0. Manual and join flows can't count down: they have no scheduled time.

Timed lines (countdown only)

offset | command sends a command when that much time is left. It is shorthand for if $timer == offset.

// Timer 60m, Before schedule, schedule 0 6 * * *
$warn = 60m 30m 15m 10m 5m 3m
$warn | say -1 Server is going to restart in @minutes minutes!
2m    | #lock
1m    | if $players > 0
  say -1 Server is going to restart in 1 minute!
  #kickall Server Restart
end
0     | #shutdown
  • Offsets are time left, with no sign: 2m is 2 minutes before the scheduled time, 0 is the scheduled time.
  • A list works as an offset: $warn | ... runs at every time in it. Lists are kept greatest first.
  • A time can start a block: 1m | if ..., or 2m | do for several lines with no condition. The lines go out one per tick from that time, so above, the warning goes out at 1m and #kickall at 59s.
  • Lines without a time run from the start of the run, one per tick.
  • Saving is refused if a time is longer than the Timer (it would never run), or a block would still be sending after 0.

Changing $timer

$timer = 3m moves the countdown, from the next tick. Moving it down skips everything in between; moving it up repeats the countdown from there. Inside an if, add a check that turns false afterwards (such as && $timer > 3m), because ifs in a countdown are checked every tick.

// Restart in 3 minutes if nobody is on
if $players == 0 && $timer > 3m
  $timer = 3m
end

Cancel

The Cancel field holds commands sent one after another when you press Stop, for example say -1 Server restart cancelled. and #unlock. A run that finishes, or ends at stop, doesn't send them.

After a restart

When the bridge logs in to the server again (after a restart), it sends #unlock, so a restart flow can end at #shutdown.

If / else / end

if $players > 0
  say -1 Locking the server now.
  #lock
else
  #lock
end
  • else and end go on lines of their own. else is optional.
  • An if can sit inside another one. There is no else if: put an if inside the else.
  • The lines inside go out one per tick, like any others.
  • In a countdown, an if outside any block is checked every tick. In other flows it is checked once, when the script reaches it.
  • The run log shows each decision, e.g. if $players > 0 -> true.

do and for each player

  • do ... end groups lines, mainly under a time: 2m | do.
  • for each player ... end runs its lines once for every player online, with $player, $name and the others set to that player.
for each player
  say $player Hi $name, your ping is $ping
end

How values compare

  • Text is compared in lower case, so Survivor, SURVIVOR and survivor are all equal.
  • Numbers and times compare as numbers (05 == 5, $timer == 5m). <, > and the others only work on numbers; on text they count as false.
  • $timer == $warn is true when $timer is any time in the list.
  • && is checked before ||, so a || b && c means a, or (b and c). There are no brackets.
  • Use "quotes" to compare against empty text: if $msg == "".

Mistakes are caught before saving

The edit dialog shows script mistakes in red as you type, with the line number: a block with no end, a number without a unit, a variable that's used but never set, a timed line outside a countdown, or setting a built-in like $players.

Rules worth knowing

  • New schedule and player-join flows are saved disabled. Press Enable to switch them on.
  • Changing an existing flow's trigger saves it disabled too, so a restart flow can never start firing on every join by accident.
  • Run works with every trigger, so you can test a scheduled flow without waiting for its time: a countdown starts at the full Timer. Flows that use $player, $name, $ip, $guid or $ping outside for each player are the exception.

On player join

// Timer 5s
say $player Welcome to our server, $name!
wait 3s
say $player Type /help for the rules.
  • The flow runs once for each player who joins, with $player, $name, $ip, $guid and $ping set to them.
  • Several players can be in progress at once; they share one log and one Stop button, which stops all of them.
  • Players already online when the app starts are not greeted. After the game server restarts, everyone who reconnects is.

Cron expressions

Five fields: minute hour day-of-month month day-of-week, in the server's time zone (set TZ on the container). The text under the field explains what you typed in plain English and shows the next three runs.

  • 0 6 * * * every day at 06:00
  • 0 */6 * * * every 6 hours (00:00, 06:00, 12:00, 18:00)
  • 30 4 * * 1,4 Mondays and Thursdays at 04:30
  • 0 5 * * 1-5 weekdays at 05:00
  • 0 3 1 * * the 1st of every month at 03:00

Field syntax

  • * any value, 1,4 a list, 1-5 a range, */15 every 15th.
  • Months and weekdays accept names: jan-dec, sun-sat. Sunday is 0 or 7.
  • If both day-of-month and day-of-week are restricted, a day matches when either does (standard cron).

Countdowns and app restarts

  • With a Timer set to Before schedule, the cron time is when the countdown reaches 0. A 60m Timer with 0 6 * * * starts the run at 05:00.
  • If the app restarts during a countdown it joins it again with the time left; timed lines that already passed are skipped. Manually started runs are not resumed.
