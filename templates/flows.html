Flow help

What a flow is

A flow is a list of steps ReCON runs for you: send a message, wait, lock the server, kick a player, and so on. Steps run from the top down; only Wait takes time, everything else goes out straight away.

Making a flow

  • Press New flow, give it a name (up to 48 characters) and pick a trigger.
  • Press + Add step to add steps. Fill in each row; anything missing is shown in red under the row.
  • Move a step with its arrows, or drag it by the ⋮⋮ handle. Moving an If moves everything inside it.
  • Save. Schedule, On join and Player message flows start disabled: press Enable when you are ready.

Times

Every time box (Wait, the delay, the chat command cooldowns) takes a number of seconds, or hours, minutes and seconds together: 30, 90s, 1m20s, 2h 15m.

The player

On join and Player message flows run for one player: the one who joined, or who typed the message. A message sent to Player goes only to them (say <their number>); Everyone is say -1. Schedule and Manual flows have no player, so they message everyone.

When stopped

Schedule and Manual flows can have steps that are sent if you press Stop before the run ends, such as Server restart cancelled. and Unlock server.

If, Else if, Else

An If compares one thing, such as {player_ping}, and runs its steps when the comparison is true. + Else if adds more comparisons of the same thing, checked top to bottom: the first one that is true runs, and the rest are skipped. + Else runs when none are true. Each If has its own End if, so they can't come apart, and Ifs can go inside other Ifs.

Reorder Else ifs with their arrows; moving one above the first makes it the If. Removing an Else if or the Else keeps its steps: they move below the End if.

Examples

  • Schedule: If {players_online} > 0 Kick everyone, Else Shut down server.
  • On join: If {player_ping} >= 500 Kick, reason Ping too high ({player_ping}).
  • Player message: If {message} starts with !discord, Message to Player Visit us at discord.gg/....

The run log under the table shows each decision, e.g. If {player_ping} >= 500: no.

The four triggers

TriggerRunsNeeds Enable
ScheduleOn a cron scheduleYes
On joinOnce for each player who finishes loading inYes
Player messageOnce for every chat message a player sendsYes
ManualWhen you press Run (or POST to /api/flows/<id>/run)No
  • Every trigger can have a delay before step 1.
  • A flow's trigger is fixed once it is saved, so a restart flow can never start firing on every join by accident. To use another trigger, make a new flow (or Export, change trigger in the file, and Import).
  • Run works for Schedule and Manual flows. On join and Player message flows run for a player, so only a player can start them.
  • On join: players already online when ReCON starts are not greeted. After the game server restarts, everyone who reconnects is.
  • Player message: ReCON finds who sent the line by their name among the players online, then uses their GUID. If two players online have the same name, their messages don't run flows.
  • Several players can be in progress at once in On join and Player message flows; they share one run log and one Stop button.

Cron expressions

Five fields: minute hour day-of-month month day-of-week, in the server's time zone (set TZ on the container). The text under the field explains what you typed and shows the next runs, with the delay added.

  • 0 6 * * * every day at 06:00
  • 0 */6 * * * every 6 hours (00:00, 06:00, 12:00, 18:00)
  • 30 4 * * 1,4 Mondays and Thursdays at 04:30
  • 0 5 * * 1-5 weekdays at 05:00
  • * any value, 1,4 a list, 1-5 a range, */15 every 15th.
  • Months and weekdays accept names: jan-dec, sun-sat. Sunday is 0 or 7.

After a restart

When ReCON logs in to the server again (after a restart), it sends #unlock, so a restart flow can end with Shut down server.

Built-in chat commands

Players type these in game chat. Chat commands (next to Import) turns each on or off, sets its cooldown and changes the wording ReCON sends. Who may use !kick and !ban is set on the Players page: Details, Permissions.

CommandDoes
!helpLists the commands; !help !vote explains one
!shout <message>Sends the message to everyone
!whisper <number> <message>Private message to that player
!playersLists everyone online with their number
!vote <question>Starts a server-wide vote; everyone answers !vote y or !vote n. More yes than no passes.
!codeSends the player's code (last 6 characters of their GUID) to the mods and admins online
!kick <code> <reason>Mods and Admins: kicks that player
!ban <code> <reason>Mods and Admins: bans that player permanently, even if they have left
  • Mods can kick and ban Players. Admins can also kick and ban Mods. Nobody can kick or ban an Admin from chat; the Kick and Ban buttons on these pages work on everyone.
  • Every mod and admin online is told about each kick and ban. Announce also tells everyone.
  • Only a command that works gets an answer. Anything else (a typo, a cooldown, no permission) is ignored; the line is still in the player's chat history.
